# `@cldmv/envm` v1.1.0 Changelog

**Release Date**: November 2026
**Release Type**: Minor
**Branch**: `release/1.1.0`

---

## Overview

envm moves to the CLDMV library layout. The package is now built with tsup into a single ESM bundle, `require("@cldmv/envm")` works through a small CommonJS entry that loads that same bundle, the package ships generated type declarations, and an `envm-dev` export condition lets a checkout run straight from `src/`. The `"."` and `"./cli"` entry points keep their paths and their exports.

This release also fixes four bugs that made parts of the API silently do nothing: the installed `envm` command never ran, Windows rollback never restored the registry backup, `unset` at user scope on Linux and macOS never removed the variable, and a name containing regex metacharacters could remove other variables.

The package now declares `engines.node` `>=22.22.0`. Earlier releases declared no floor at all; see the upgrade notes.

---

## ✨ Features

### CLDMV library layout with a CommonJS entry ([#60](https://github.com/CLDMV/envm/pull/60), closes [#59](https://github.com/CLDMV/envm/issues/59))

- **tsup build.** The old `esbuild` command wrote one unbundled file per source module. tsup now builds `dist/index.mjs` (the library, with the platform adapters and backup helpers bundled in) and `dist/cli.mjs` (the CLI, which keeps its `./index.mjs` import external so it loads the library bundle instead of carrying a second copy). Output is minified with function names kept. The library plus CLI is about 15 KB minified, down from about 29 KB.
- **`require()` support.** `src/index.cjs` is a short wrapper that `require()`s the sibling `index.mjs` through Node's `require(esm)` and re-exports `{ envManager }`. It is copied verbatim to `dist/index.cjs`, so CommonJS and ESM callers share one copy of the library and its state. On a Node.js version without `require(esm)` it throws `ERR_REQUIRE_ESM` with a message naming the supported range and pointing at `import()`.
- **Type declarations.** `types/` is generated from the JSDoc by `tsc` and published; `exports` carries a `types` condition for both entry points. `envManager` is typed through explicit `EnvManager`, `PathHelpers` and `BackupHelpers` typedefs so its declaration emits as a typed `const` ([#63](https://github.com/CLDMV/envm/pull/63)).
- **`envm-dev` export condition.** `"."` and `"./cli"` resolve to `dist/` by default. In a checkout, `node --conditions=envm-dev` resolves them to `src/` instead. The Vitest suite runs against `src/` through the condition, and `npm run test:dist` builds the package and checks the built entries with `node --test`.
- **Shared backup state in the CLI.** The CLI's exit-time purge now goes through `envManager.backup`, so it uses the same backup directory as the library rather than a separately loaded copy of `backup.mjs`.
- `package.json` gains `main` (`./dist/index.cjs`), `module`, `types`, a `./package.json` export, and a `prepack` build in place of `prepublishOnly`.

## 🐛 Bug Fixes

### The installed `envm` command did nothing ([#60](https://github.com/CLDMV/envm/pull/60), fixes [#61](https://github.com/CLDMV/envm/issues/61))

`src/cli.mjs` only ran `main()` when `import.meta.url` equalled `` `file://${process.argv[1]}` ``. An installed `envm` runs through the `node_modules/.bin/envm` symlink, so `process.argv[1]` was the link path, the check failed and the command exited without doing anything. Paths containing URL-encoded characters such as spaces failed the same way. The check now compares `fileURLToPath(import.meta.url)` with `realpathSync(process.argv[1])`. The CLI file also starts with a `#!/usr/bin/env node` line, which the published bin lacked.

### Windows rollback never restored the registry backup ([#60](https://github.com/CLDMV/envm/pull/60), fixes [#62](https://github.com/CLDMV/envm/issues/62))

When verification failed after a `set` or `unset` at user or system scope, the rollback path called `require("os")` and `require("fs")`. `require` is not defined in an ES module, so it threw a `ReferenceError`, the surrounding `catch` swallowed it, and the registry backup was never imported. Rollback now uses the module's own imports and works.

### `unset` at user scope never removed the variable on Linux and macOS ([#60](https://github.com/CLDMV/envm/pull/60))

The filter for `~/.profile` lines was a `RegExp` built from a template literal, where `\s` lost its backslash and the pattern became `^exports+NAME=`. It never matched, so the `export` line stayed in the envm block and the variable survived the `unset`. The filter now parses each `export NAME=` line and compares the name literally, which also fixes the next item.

### Variable names were treated as regex patterns ([#60](https://github.com/CLDMV/envm/pull/60))

Because that filter interpolated the variable name into a `RegExp`, metacharacters in the name matched other variables: unsetting `A.B` would also remove `AxB`. Names are now compared as plain strings.

### Registry import files went to a predictable temp path ([#60](https://github.com/CLDMV/envm/pull/60))

Windows rollback and `backup.restore()` wrote the `.reg` file to a fixed-pattern name in the shared temp directory, and `restore()` never deleted it. All three paths now go through one helper that creates a private directory with `mkdtemp`, writes the file with exclusive create and mode `0600`, runs `reg import`, and removes the directory afterwards.

## 🔧 CI & tooling

- **Node.js floor raised to 22.22.0** ([#60](https://github.com/CLDMV/envm/pull/60)). The dev toolchain (`tsup` 9 and its `chokidar` 6 dependency) needs Node.js 22.22, so nothing older can be built or tested. `engines.node`, the CommonJS guard's message and the CI matrix floor (previously 22.12.0) move together. The layout work first set `^20.19.0 || >=22.13.0`; that never shipped.
- `build:ci` now runs lint, the format check, the declaration build and the tsup build; the CI coverage legs run `build:ci`, and the bundle-size check measures the `.mjs` and `.cjs` files in `dist/`.
- ESLint and Prettier configs moved to `.configs/` on the shared CLDMV base, with `lint`, `lint:fix`, `format` and `format:check` scripts and a `.prettierignore`; the existing lint errors were cleared. The leftover `jest.config.mjs` is gone.
- TypeScript is pinned to 6 for the declaration build, because TypeScript 7's JavaScript declaration emit isn't complete yet, and the declarations were regenerated with it ([#63](https://github.com/CLDMV/envm/pull/63)).

## Upgrade notes

- **Node.js 22.22.0 or later is now required.** v1.0.12 and earlier declared no `engines` field. On an older Node.js, npm warns with `EBADENGINE` on install (or refuses, with `engine-strict`), and those versions are no longer built or tested.
- `import { envManager } from "@cldmv/envm"` and the `envm` command work as before. `require("@cldmv/envm")` now works too and returns the same `envManager`.
- The installed `envm` command now actually runs, so scripts that called it and silently got no effect will start changing environment variables. Windows rollback and user-scope `unset` on Linux and macOS now do what they always claimed to.
